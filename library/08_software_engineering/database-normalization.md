# 데이터베이스 정규화 / Database Normalization

데이터 중복을 최소화하고 무결성을 보장하기 위해 테이블을 분리하는 과정입니다.

The process of organizing data to minimize redundancy and ensure integrity by decomposing tables.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

여러분, **사물함 정리**를 생각해 봐요! 사물함이 지저분하면 원하는 것을 찾기 어렵죠? 데이터베이스 정규화는 **데이터를 깔끔하게 정리하는 방법**이에요!

예를 들어, 반 친구들의 연락처를 적는다고 해 봐요:

**정리 전 (지저분):**
| 이름 | 전화번호 | 좋아하는 과목 |
| 민수 | 010-1234, 010-5678 | 수학, 과학 |

→ 전화번호가 2개! 과목도 2개! 한 칸에 여러 개가 들어있어서 지저분해요.

**정리 후 (깔끔):**
| 이름 | 전화번호 |
| 민수 | 010-1234 |
| 민수 | 010-5678 |

→ 한 칸에 하나씩! 이렇게 정리하는 첫 번째 단계가 **1정규형(1NF)**이에요.

정규화는 이처럼 **데이터를 깔끔하게 나누고 정리하는 과정**이에요. 방 청소처럼 단계별로 점점 깔끔해진답니다!

### 📐 중학생 눈높이

학교 도서관 시스템의 데이터를 정리해 볼까요?

**정규화 전 (비정규형):**
| 대출id | 학생이름 | 학년 | 반 | 책제목 | 저자 | 대출일 |
| 1 | 민수 | 2 | 3 | 해리포터 | 롤링 | 2024-01-01 |
| 2 | 민수 | 2 | 3 | 반지의제왕 | 톨킨 | 2024-01-05 |

문제점이 보이나요? **민수의 학년, 반 정보가 중복**돼요! 민수가 3학년이 되면 두 줄 다 수정해야 해요.

**1NF:** 한 칸에 하나의 값만! (원자값)
**2NF:** 학생 정보(이름, 학년, 반)를 별도 테이블로 분리!
**3NF:** 저자 정보도 책과 분리!

이렇게 **중복을 제거하고 테이블을 나누면**, 데이터를 수정할 때 한 곳만 고치면 돼요. 마치 코드에서 함수를 분리하는 것과 같은 원리예요!

### 🎓 고등학생 눈높이

데이터베이스 정규화는 **Edgar F. Codd**가 1970년에 제안한 관계형 데이터 모델의 핵심 이론이에요:

- **함수 종속성(Functional Dependency):** X → Y는 "X가 결정되면 Y가 결정된다"는 의미
- **1NF~BCNF**가 실무에서 주로 사용되고, 4NF, 5NF는 학술적 의미가 더 커요
- 정규화를 과하게 하면 JOIN이 많아져 **성능이 떨어질** 수 있어요
- 그래서 의도적으로 중복을 허용하는 **역정규화(Denormalization)**도 사용해요
- **DBA, 데이터 엔지니어** 직군에서 정규화 역량은 필수예요
- 데이터베이스 설계 시 **"정규화 → 성능 테스트 → 필요시 역정규화"** 순서로 진행해요

## 🔍 어떻게 작동하는지 알아볼까요?

정규화의 각 단계를 순서대로 따라가 볼게요:

**비정규형 (UNF) - 정리 안 된 상태**
- 한 칸에 여러 값이 들어있고, 데이터가 중복되는 상태예요
- 이대로 사용하면 데이터 일관성이 깨질 수 있어요

**제1정규형 (1NF) - "원자값 보장"**
- 모든 속성(칸)에 **하나의 값만** 들어가야 해요
- 전화번호가 "010-1234, 010-5678"이면 안 돼요 → 행을 분리!

**제2정규형 (2NF) - "부분 종속 제거"**
- 기본키의 **일부에만 종속**된 속성을 별도 테이블로 분리해요
- 예: (학생id, 과목id) 복합키에서 학생이름은 학생id에만 종속 → 분리!

**제3정규형 (3NF) - "이행 종속 제거"**
- A → B → C 에서, A → C를 직접 두지 않아요
- 예: 학생id → 학과 → 학과전화번호 에서, 학과전화번호를 학과 테이블로 분리!

**BCNF (보이스-코드 정규형) - "더 엄격한 3NF"**
- 모든 결정자가 후보키여야 해요
- 3NF보다 더 엄격한 조건이지만, 실무에서는 3NF와 BCNF를 구분해야 하는 경우는 드물어요

핵심은 **"중복을 없애고 → 한 곳에서만 수정하면 되도록"** 만드는 것이에요!

## 정규형 요약

| 정규형 | 조건 | 예시 |
|--------|------|------|
| 1NF | 모든 속성이 원자값 | 전화번호 여러 개 → 별도 행 |
| 2NF | 부분 함수 종속 제거 | 복합 키의 일부에만 종속된 속성 분리 |
| 3NF | 이행 함수 종속 제거 | A→B→C에서 C를 별도 테이블로 |
| BCNF | 모든 결정자가 후보키 | 더 엄격한 3NF |

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 다이어그램에서 비정규형(빨간색)에서 BCNF(파란색)로 갈수록 색이 밝아지는 것이 보이나요? 각 화살표 위에 어떤 종속성을 제거하는지 적혀 있어요. 분해 과정 슬라이더를 조절하면 테이블이 어떻게 나뉘어지는지 단계별로 볼 수 있어요.
- **관찰 결과:** 정규화의 각 단계는 **특정한 종류의 중복을 제거**해요. 비정규형(빨강)에서 BCNF(파랑)로 갈수록 데이터의 무결성은 높아지지만, 테이블 수가 늘어나고 JOIN이 많아져요. 이것이 **정규화와 성능 사이의 트레이드오프**랍니다.
- **연결 질문:** "인스타그램처럼 읽기 작업이 매우 많은 서비스에서, 3NF까지 정규화하면 JOIN이 많아져서 느려질 수 있어요. 이때 어떤 전략을 사용하면 좋을까요?"

## 🔗 개념 연결 고리

- ➡️ **ER 다이어그램** (er-diagram): ER 다이어그램으로 설계한 뒤 정규화를 적용해요
- ↔️ **역정규화 (Denormalization)**: 성능을 위해 의도적으로 중복을 허용하는 반대 개념이에요
- ➡️ **마이크로서비스 아키텍처** (microservices-architecture): 서비스별 DB 분리와 정규화 수준이 다를 수 있어요
- ➡️ **SDLC** (sdlc): 데이터베이스 설계는 SDLC의 설계 단계에서 이루어져요

## 실생활 활용

- **관계형 데이터베이스 설계** - MySQL, PostgreSQL, Oracle 등 RDBMS를 사용하는 모든 서비스에서 정규화는 기본이에요. 테이블 설계의 첫 단계에서 반드시 거치는 과정이랍니다.
- **데이터 품질 관리** - 정규화가 잘 되어 있으면 데이터 불일치(anomaly)가 방지돼요. "주소를 여기서 바꿨는데 저기는 안 바뀌었네?" 같은 문제가 사라져요.
- **성능 최적화 (역정규화)** - 정규화를 먼저 하고, 성능이 필요한 부분만 역정규화해요. 예를 들어 대시보드에 필요한 집계 데이터를 미리 계산해서 별도 테이블에 저장하는 것이 역정규화예요.
- **데이터 마이그레이션** - 레거시 시스템의 비정규화된 데이터를 정규화하여 새 시스템으로 이관하는 프로젝트가 많아요.
- **면접 준비** - "1NF, 2NF, 3NF의 차이를 설명하세요"는 백엔드 개발자 면접에서 자주 나오는 질문이에요!
