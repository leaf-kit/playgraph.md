# 이진 탐색 트리 / Binary Search Tree

왼쪽 자식은 부모보다 작고, 오른쪽 자식은 부모보다 큰 이진 트리입니다.

A binary tree where left < parent < right for all nodes.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

이진 탐색 트리는 **숫자 찾기 놀이**와 같아요! 선생님이 "50보다 큰가요?"라고 물으면, "네"라면 오른쪽으로, "아니오"라면 왼쪽으로 가요. 이렇게 매번 반씩 줄여가면서 찾으니까 정말 빨라요! 100명 중에서도 몇 번만 물어보면 찾을 수 있답니다.

### 📐 중학생 눈높이

사전을 찾을 때를 생각해 보세요. "banana"를 찾으려면 사전을 반쯤 펼치고, "b"가 앞쪽이니까 앞으로 가죠. 다시 반을 펼치고... BST도 이렇게 작동해요! 각 노드에서 "찾는 값이 더 크면 오른쪽, 작으면 왼쪽"으로 가면서 빠르게 찾아요. 하지만 주의할 점이 있어요 — 데이터가 이미 정렬된 상태로 들어오면 한쪽으로만 치우쳐져서 느려질 수 있어요!

### 🎓 고등학생 눈높이

BST는 이진 트리에 정렬 불변성(invariant)을 추가한 자료구조입니다. 중위 순회(inorder traversal)하면 정렬된 결과를 얻을 수 있어요. 평균적으로 탐색/삽입/삭제가 O(log n)이지만, 편향 트리(skewed tree)가 되면 O(n)으로 퇴화합니다. 이를 방지하기 위해 AVL 트리, Red-Black 트리 같은 자가 균형 BST가 개발되었어요. Rust의 BTreeMap은 B-트리 기반으로 캐시 효율성이 뛰어납니다.

## 🔍 어떻게 작동하는지 알아볼까요?

**BST의 핵심 연산을 따라가 봐요!**

1. **규칙**: 왼쪽 자식 < 부모 < 오른쪽 자식 (항상!)
2. **삽입**: 루트부터 시작해서 크기 비교하며 내려가다가 빈 자리에 넣어요
   - 트리 [8, 3, 10]에 6 삽입 → 8보다 작으니 왼쪽 → 3보다 크니 오른쪽 → [8, 3, 10, _, 6]
3. **탐색**: 비교하며 내려가면 끝!
   - 6 찾기: 8보다 작아→왼쪽, 3보다 커→오른쪽 → 찾았다!
4. **삭제**: 세 가지 경우가 있어요
   - 리프 노드: 그냥 제거
   - 자식 1개: 자식을 올려보내기
   - 자식 2개: 오른쪽 서브트리의 최솟값으로 대체
5. **중위 순회**: 왼→루트→오른 순서로 방문하면 정렬된 결과!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 탐색 값을 입력하면, 루트부터 비교하며 경로가 하이라이트되는 것을 볼 수 있어요. 매번 한쪽 절반을 건너뛰는 것이 보이죠!
- **관찰 결과:** 균형 잡힌 BST에서는 매 단계마다 탐색 범위가 절반으로 줄어들어요. 그래서 1000개의 데이터에서도 약 10번의 비교만으로 원하는 값을 찾을 수 있답니다.
- **연결 질문:** 만약 1, 2, 3, 4, 5를 순서대로 BST에 삽입하면 어떤 모양이 될까요? 이 문제를 어떻게 해결할 수 있을까요?

## 실생활 활용

- **사전 검색** — 단어를 알파벳 순서의 규칙으로 빠르게 찾을 수 있어요
- **데이터베이스 인덱스** — 수백만 건의 레코드에서 원하는 데이터를 log n만에 찾아요
- **자동 완성** — 입력한 글자보다 큰 값들을 빠르게 범위 검색할 수 있어요
- **게임 랭킹 시스템** — 점수를 BST에 넣으면 자동으로 순위가 결정돼요
- **파일 시스템 인덱싱** — 파일 이름을 BST로 관리하면 검색이 빨라져요

## 🔗 개념 연결 고리

- **이진 트리(Binary Tree)**: BST의 기반이 되는 자료구조. 여기에 정렬 규칙을 추가한 것이 BST예요
- **이진 탐색(Binary Search)**: 정렬된 배열에서의 이진 탐색과 BST의 탐색은 같은 원리예요
- **힙(Heap)**: BST와 다른 정렬 규칙을 가진 트리. BST는 좌우 비교, 힙은 부모-자식 비교예요

## 핵심 정리

> 평균 탐색 O(log n), 최악 O(n)
