# 트라이 / Trie

문자열을 효율적으로 저장하고 검색하기 위한 트리 기반 자료구조입니다.

A tree-based data structure for efficiently storing and searching strings.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

트라이는 **끝말잇기 사전**을 떠올려 보세요! "사"로 시작하는 단어를 찾고 싶으면, "사" 서랍을 열어요. 그 안에 "사과", "사람", "사탕" 등이 있죠. "사과"를 찾으려면 "사" → "과" 순서로 서랍을 열면 돼요. 같은 글자로 시작하는 단어들이 같은 길을 공유하니까 공간도 아끼고 찾기도 빨라요!

### 📐 중학생 눈높이

핸드폰에서 글자를 치면 자동완성 추천이 뜨죠? "app"을 치면 "apple", "application", "apply"가 나와요. 이 세 단어 모두 "app"이라는 같은 경로를 공유해요. 트라이는 이처럼 **공통 접두사(prefix)를 공유**하는 자료구조예요. 한 글자씩 따라가면서 검색하므로, 단어 길이만큼만 시간이 걸려요!

### 🎓 고등학생 눈높이

트라이(prefix tree)는 문자열을 문자 단위로 트리에 저장하여 접두사 기반 탐색을 O(m)(m: 문자열 길이)에 수행합니다. 해시 테이블보다 접두사 검색에 유리하고, 정렬된 순서의 데이터 순회도 가능해요. 메모리 사용량이 클 수 있어 압축 트라이(Patricia trie / radix tree)로 최적화하기도 합니다. 자동 완성, 사전 구현, IP 라우팅, 스펠 체커 등에 핵심적으로 사용됩니다.

## 🔍 어떻게 작동하는지 알아볼까요?

**트라이의 동작을 단계별로 따라가 봐요!**

1. **루트**: 빈 노드에서 시작해요
2. **삽입 "cat"**: 루트 → c → a → t (★표시: 단어 끝)
3. **삽입 "car"**: 루트 → c → a (이미 있음!) → r (★)
   - "ca"까지는 "cat"과 같은 경로를 공유해요!
4. **삽입 "dog"**: 루트 → d → o → g (★) — 새 경로가 만들어져요
5. **검색 "car"**: 루트 → c → a → r → ★ 있음! → 찾았다!
6. **검색 "cab"**: 루트 → c → a → b? → 없음! → 단어 없음
7. **접두사 검색 "ca"**: c → a에서 아래 모든 경로 탐색 → "cat", "car" 반환!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 단어를 추가할 때, 이미 존재하는 접두사 부분은 새 노드를 만들지 않고 기존 경로를 재사용하는 것을 볼 수 있어요.
- **관찰 결과:** 비슷한 단어가 많을수록 트라이가 효율적이에요! 공통 접두사를 공유하니까 메모리도 아끼고, 접두사로 검색하면 관련 단어를 모두 한꺼번에 찾을 수 있어요.
- **연결 질문:** 해시 테이블로도 단어를 저장할 수 있는데, 왜 굳이 트라이를 쓸까요? "ca"로 시작하는 모든 단어를 찾으려면 어떤 자료구조가 더 유리할까요?

## 실생활 활용

- **자동 완성 기능** — 검색창에 글자를 입력하면 추천 단어가 뜨는 것이 트라이 덕분이에요
- **스펠링 체크** — 입력한 단어가 사전에 있는지 빠르게 확인해요
- **IP 라우팅 테이블** — 네트워크에서 IP 주소의 접두사를 매칭하여 경로를 결정해요
- **T9 예측 입력** — 옛날 핸드폰에서 숫자 키로 글자를 예측하던 기술이에요
- **DNA 서열 분석** — 유전자 서열(A, T, G, C)의 패턴을 빠르게 검색할 수 있어요

## 🔗 개념 연결 고리

- **해시 테이블(Hash Table)**: 정확한 키 검색은 해시 테이블이, 접두사 검색은 트라이가 유리해요
- **이진 탐색 트리(BST)**: BST도 정렬된 탐색이 가능하지만, 문자열에는 트라이가 더 효율적이에요
- **그래프 탐색**: 트라이에서 단어 찾기는 DFS와 비슷한 방식으로 동작해요

## 핵심 정리

> 검색/삽입 O(m), m은 문자열 길이. 접두사 검색에 최적화.
