# 퀵 정렬 / Quick Sort

피벗을 기준으로 작은 값과 큰 값을 분할하여 정렬하는 알고리즘입니다.

Divide and conquer sorting using a pivot element.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

퀵 정렬은 **"기준 친구"를 정하는 놀이**예요! 한 친구를 기준으로 세우고, 나머지 친구들은 "기준보다 키가 작으면 왼쪽, 크면 오른쪽"으로 가요. 그다음 왼쪽 그룹과 오른쪽 그룹에서도 같은 놀이를 해요. 이렇게 반복하면 모두가 키 순서대로 서게 돼요!

### 📐 중학생 눈높이

시험지를 빠르게 점수순으로 정리한다고 생각해 보세요. 아무 시험지 하나를 집어서 "이것보다 낮은 점수는 왼쪽, 높은 점수는 오른쪽"으로 나눠요. 그리고 각 더미에서도 같은 방법을 반복! 이 "기준"을 **피벗(pivot)**이라고 해요. 좋은 피벗을 고르면 아주 빠르지만(O(n log n)), 최악의 피벗(항상 최솟값이나 최댓값)을 고르면 느려질 수 있어요(O(n²)).

### 🎓 고등학생 눈높이

퀵 정렬은 평균 O(n log n), 최악 O(n²)의 분할 정복 정렬입니다. 피벗 선택 전략(랜덤, 중앙값의 중앙값 등)이 성능에 결정적이에요. 제자리 정렬(in-place)이라 추가 메모리가 O(log n)(재귀 스택)뿐이지만, 불안정 정렬(unstable sort)입니다. C의 qsort, Java의 Arrays.sort(기본형), Rust의 sort_unstable이 퀵 정렬 기반이에요. 캐시 지역성이 좋아서 실제 성능은 병합 정렬보다 빠른 경우가 많아요.

## 🔍 어떻게 작동하는지 알아볼까요?

**배열 [6, 3, 8, 1, 5, 2, 7, 4]를 퀵 정렬해 봐요! (피벗: 마지막 원소)**

1. **피벗 선택**: 4를 피벗으로!
2. **파티션**: 4보다 작은 것 왼쪽, 큰 것 오른쪽
   - [3, 1, 2] **4** [6, 8, 5, 7] → 4는 자기 자리 확정!
3. **왼쪽 [3, 1, 2] 정렬** (피벗: 2):
   - [1] **2** [3] → 2 확정!
4. **오른쪽 [6, 8, 5, 7] 정렬** (피벗: 7):
   - [6, 5] **7** [8] → 7 확정!
5. **[6, 5] 정렬** (피벗: 5):
   - [] **5** [6] → 5 확정!
6. **결과**: [1, 2, 3, 4, 5, 6, 7, 8] 정렬 완료!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 피벗이 선택되면, 원소들이 피벗을 기준으로 좌우로 나뉘는 파티션 과정을 볼 수 있어요. 피벗은 매번 자기 최종 위치에 고정돼요!
- **관찰 결과:** 좋은 피벗(중앙값에 가까운)은 배열을 균등하게 나누어 O(n log n)을 만들지만, 나쁜 피벗(최솟값/최댓값)은 한쪽으로 치우쳐 O(n²)이 돼요. 피벗 선택이 성능의 핵심!
- **연결 질문:** 이미 정렬된 배열에서 항상 첫 번째 원소를 피벗으로 고르면 어떻게 될까요? 이 문제를 어떻게 피할 수 있을까요?

## 실생활 활용

- **프로그래밍 언어 내장 정렬** — C, Java, Rust 등 대부분의 언어 라이브러리가 퀵 정렬(변형)을 사용해요
- **대규모 데이터 정렬** — 캐시 효율이 좋아서 실제 대용량 데이터에서 가장 빠른 정렬 중 하나예요
- **데이터 분석** — 중앙값, 백분위 계산 시 파티션 기법을 활용해요 (QuickSelect)
- **검색 엔진** — 검색 결과를 관련도 순으로 빠르게 정렬해요
- **게임 렌더링** — 오브젝트를 거리순으로 정렬할 때 퀵 정렬의 속도가 중요해요

## 🔗 개념 연결 고리

- **병합 정렬(Merge Sort)**: 퀵 정렬은 "나눌 때" 정렬, 병합 정렬은 "합칠 때" 정렬. 둘 다 분할 정복!
- **버블 정렬(Bubble Sort)**: O(n²) vs O(n log n) — 성능 차이가 얼마나 큰지 비교해 보세요
- **재귀(Recursion)**: 퀵 정렬의 분할 정복은 재귀로 자연스럽게 구현돼요

## 핵심 정리

> 평균 O(n log n), 최악 O(n²)
