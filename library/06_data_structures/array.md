# 배열 / Array

같은 타입의 데이터를 연속된 메모리 공간에 저장하는 자료구조입니다.

A contiguous block of memory storing elements of the same type.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

배열은 **사물함**을 떠올리면 돼요! 학교 복도에 1번, 2번, 3번... 순서대로 번호가 붙은 사물함이 쭉 나란히 있죠? 각 사물함에 물건을 하나씩 넣을 수 있고, 번호만 알면 바로 찾아갈 수 있어요. "3번 사물함 열어!"하면 바로 열 수 있는 것처럼, 배열도 인덱스(번호)만 알면 데이터를 바로 찾을 수 있답니다.

### 📐 중학생 눈높이

게임에서 인벤토리를 생각해 보세요. 10칸짜리 인벤토리가 있으면, 각 칸에 아이템을 하나씩 넣을 수 있어요. 5번째 칸에 뭐가 있는지 바로 확인할 수 있죠. 그런데 3번째 칸에 새 아이템을 끼워 넣으려면? 뒤의 아이템들을 모두 한 칸씩 밀어야 해요. 이것이 바로 배열의 **삽입이 느린 이유**예요. 배열이 중요한 이유는 컴퓨터의 거의 모든 데이터 저장이 배열에서 시작하기 때문이에요.

### 🎓 고등학생 눈높이

배열은 **연속된 메모리 블록**에 데이터를 저장합니다. 메모리 주소가 연속적이기 때문에 `base_address + index * element_size`로 O(1)에 임의 접근이 가능해요. 하지만 삽입/삭제 시 요소들을 시프트해야 하므로 O(n)이 됩니다. CPU 캐시 친화적(cache-friendly)이라 실제 성능에서 연결 리스트보다 유리한 경우가 많아요. Rust에서는 `Vec<T>`가 동적 배열을 구현하며, 고정 크기 배열 `[T; N]`은 스택에 할당됩니다.

## 🔍 어떻게 작동하는지 알아볼까요?

**배열의 핵심 연산을 단계별로 살펴봐요!**

1. **생성**: 크기를 정해서 연속된 메모리 공간을 확보해요. 예: 크기 5인 배열 → `[_, _, _, _, _]`
2. **접근(Read)**: 인덱스로 바로 접근! `arr[2]` → 세 번째 칸의 값을 즉시 가져와요 (O(1))
3. **삽입(Insert)**: 중간에 넣으려면 뒤의 요소들을 모두 한 칸씩 밀어야 해요
   - `[1, 2, 4, 5]`에서 인덱스 2에 3을 삽입 → `[1, 2, 3, 4, 5]` (O(n))
4. **삭제(Delete)**: 중간 요소를 빼면 빈자리를 메우기 위해 앞으로 당겨야 해요
   - `[1, 2, 3, 4, 5]`에서 인덱스 1 삭제 → `[1, 3, 4, 5, _]` (O(n))
5. **탐색(Search)**: 정렬되지 않은 배열은 하나씩 확인 (O(n)), 정렬된 배열은 이진 탐색 가능 (O(log n))

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 인덱스를 선택하면 해당 칸이 바로 하이라이트되는 것을 볼 수 있어요. 주소 보기를 켜면 각 칸의 메모리 주소가 일정한 간격으로 증가하는 것도 확인할 수 있죠.
- **관찰 결과:** 배열의 인덱스 접근이 O(1)인 이유는 메모리 주소가 연속적이기 때문이에요. 컴퓨터는 계산 한 번으로 원하는 위치의 주소를 알아낼 수 있답니다.
- **연결 질문:** 만약 배열의 크기를 미리 정하지 않아도 된다면 어떨까요? 그런 자료구조가 있을까요? (힌트: 연결 리스트를 살펴보세요!)

## 실생활 활용

- **이미지 픽셀 저장** — 사진 한 장은 수백만 개의 픽셀로 이루어져 있고, 각 픽셀의 색상 값이 배열에 저장돼요
- **학생 성적표** — 한 반 학생들의 점수를 번호 순서대로 저장하면 몇 번 학생 점수든 바로 찾을 수 있어요
- **게임 인벤토리** — RPG 게임의 아이템 슬롯이 바로 배열이에요. 칸 번호로 바로 접근하죠
- **센서 데이터 수집** — IoT 기기에서 매초 측정한 온도 데이터를 순서대로 배열에 기록해요
- **엑셀 스프레드시트** — 행과 열로 이루어진 셀은 사실 2차원 배열이에요

## 🔗 개념 연결 고리

- **연결 리스트(Linked List)**: 배열의 삽입/삭제 단점을 보완한 자료구조예요. 둘의 장단점을 비교해 보세요!
- **이진 탐색(Binary Search)**: 정렬된 배열에서 사용할 수 있는 강력한 탐색 알고리즘이에요
- **해시 테이블(Hash Table)**: 배열을 기반으로 만들어진 더 빠른 검색 자료구조예요

## 핵심 정리

> 접근 O(1), 삽입/삭제 O(n)
