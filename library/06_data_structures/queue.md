# 큐 / Queue

선입선출(FIFO) 원칙을 따르는 자료구조입니다.

A First-In-First-Out (FIFO) data structure.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

큐는 **급식 줄**이에요! 먼저 줄을 선 친구가 먼저 밥을 받죠? 새로 온 친구는 줄 맨 뒤에 서야 해요. 새치기는 안 돼요! "먼저 온 사람이 먼저 나간다"는 공정한 규칙, 이것이 바로 큐예요.

### 📐 중학생 눈높이

놀이공원 대기줄을 떠올려 보세요. 먼저 온 사람이 먼저 놀이기구를 타고, 나중에 온 사람은 뒤에서 기다리죠. 프린터도 마찬가지예요 — 먼저 보낸 문서가 먼저 인쇄돼요. 큐는 **순서를 공정하게 관리**할 때 꼭 필요한 자료구조예요. BFS(너비 우선 탐색)에서도 방문할 노드를 큐에 넣어서 순서대로 처리한답니다.

### 🎓 고등학생 눈높이

큐는 FIFO(First-In-First-Out) 원칙을 따르며, enqueue(삽입)와 dequeue(제거)가 모두 O(1)입니다. 원형 큐(circular queue)는 배열 기반으로 효율적으로 구현할 수 있고, 우선순위 큐(priority queue)는 힙으로 구현됩니다. 운영체제의 프로세스 스케줄링, 네트워크 패킷 처리, 이벤트 루프(event loop) 등 시스템 프로그래밍의 핵심 자료구조예요. 메시지 큐(RabbitMQ, Kafka)는 분산 시스템에서 비동기 통신의 기반이 됩니다.

## 🔍 어떻게 작동하는지 알아볼까요?

**큐의 연산을 단계별로 따라가 봐요!**

1. **빈 큐 생성**: `Front → [ ] ← Rear`
2. **Enqueue(넣기)**: 뒤쪽(Rear)에 추가!
   - Enqueue 10 → `Front → [10] ← Rear`
   - Enqueue 20 → `Front → [10, 20] ← Rear`
   - Enqueue 30 → `Front → [10, 20, 30] ← Rear`
3. **Peek(확인)**: 맨 앞(Front) 값을 확인 → 10
4. **Dequeue(빼기)**: 앞쪽(Front)에서 꺼내요!
   - Dequeue → 10 반환, 큐: `Front → [20, 30] ← Rear`
   - Dequeue → 20 반환, 큐: `Front → [30] ← Rear`
5. **특징**: 넣는 곳(Rear)과 빼는 곳(Front)이 달라요!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 Enqueue하면 오른쪽(뒤)에 추가되고, Dequeue하면 왼쪽(앞)에서 제거되는 것을 볼 수 있어요. 양쪽 끝에서 동작이 일어나죠!
- **관찰 결과:** 큐는 입구와 출구가 다르기 때문에 순서가 보장돼요. 이 특성 덕분에 "공정한 처리"가 필요한 모든 곳에서 사용됩니다.
- **연결 질문:** 만약 양쪽 모두에서 넣고 뺄 수 있다면 어떨까요? 그런 자료구조를 "덱(Deque)"이라고 해요. 어디에 쓸 수 있을까요?

## 실생활 활용

- **프린터 대기열** — 문서를 보낸 순서대로 인쇄돼요. 나중에 보낸 문서가 먼저 나오면 안 되겠죠!
- **콜센터 대기** — "고객님, 앞에 3명의 대기자가 있습니다." 바로 큐예요!
- **BFS 탐색** — 그래프를 가까운 노드부터 탐색할 때 큐를 사용해요
- **유튜브/넷플릭스 버퍼링** — 영상 데이터가 큐에 쌓였다가 순서대로 재생돼요
- **카카오톡 메시지** — 보낸 순서대로 상대방에게 전달돼요. 큐가 순서를 보장해요!

## 🔗 개념 연결 고리

- **스택(Stack)**: 큐와 반대인 LIFO 자료구조. 둘의 차이를 꼭 비교해 보세요!
- **BFS와 DFS**: BFS는 큐를, DFS는 스택을 사용해요. 탐색 순서가 완전히 달라져요
- **연결 리스트(Linked List)**: 큐를 효율적으로 구현하는 데 연결 리스트가 사용돼요

## 핵심 정리

> Enqueue/Dequeue O(1)
