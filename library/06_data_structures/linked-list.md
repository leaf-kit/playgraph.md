# 연결 리스트 / Linked List

각 노드가 데이터와 다음 노드의 포인터를 가진 자료구조입니다.

A sequence of nodes where each node points to the next.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

연결 리스트는 **보물찾기 게임**과 같아요! 첫 번째 쪽지에 "다음 쪽지는 나무 아래에 있어"라고 적혀 있고, 나무 아래 쪽지에는 "다음은 벤치 밑!"이라고 적혀 있죠. 각 쪽지가 다음 쪽지의 위치를 알려주는 거예요. 새 쪽지를 중간에 끼우려면? 앞 쪽지의 "다음 위치"만 바꿔주면 끝! 사물함처럼 전부 옮길 필요가 없어요.

### 📐 중학생 눈높이

기차를 생각해 보세요. 각 객차(노드)는 짐(데이터)을 싣고 있고, 연결고리(포인터)로 다음 객차와 이어져 있어요. 새 객차를 중간에 넣으려면 연결고리만 바꾸면 되죠 — 정말 빠르죠! 하지만 "5번째 객차에 뭐가 있지?"라고 물으면 처음부터 하나씩 세어 가야 해요. 이것이 배열과 가장 큰 차이점이에요. **언제 뭘 쓸지 아는 것**이 프로그래머의 실력이랍니다.

### 🎓 고등학생 눈높이

연결 리스트는 비연속 메모리에 저장된 노드들이 포인터로 연결된 자료구조입니다. 삽입/삭제가 O(1)이지만 임의 접근이 O(n)이에요. 단일 연결 리스트, 이중 연결 리스트, 원형 연결 리스트 등 변형이 있으며, 이중 연결 리스트는 양방향 탐색이 가능합니다. 실제로 운영체제의 프로세스 관리, 메모리 할당 해제 목록(free list) 등에 활용돼요. 다만 캐시 지역성(cache locality)이 떨어져 현대 하드웨어에서는 배열 기반 자료구조가 더 빠른 경우가 많다는 점도 알아두세요.

## 🔍 어떻게 작동하는지 알아볼까요?

**연결 리스트의 핵심 연산을 따라가 봐요!**

1. **노드 구조**: 각 노드는 `[데이터 | 다음 포인터]`로 구성돼요
2. **탐색**: 항상 Head(머리)부터 시작해서 포인터를 따라가요
   - Head → [10|→] → [20|→] → [30|→] → null
3. **삽입**: 원하는 위치의 앞 노드의 포인터만 변경하면 끝!
   - 20 뒤에 25 삽입: [20|→]의 포인터를 [25|→]로, [25|→]의 포인터를 [30|→]으로
4. **삭제**: 삭제할 노드를 건너뛰도록 포인터를 연결해요
   - 20 삭제: [10|→]의 포인터를 바로 [30|→]으로 변경
5. **끝 확인**: 포인터가 null이면 리스트의 끝이에요

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 노드를 삽입할 때, 화살표(포인터)의 방향만 바뀌고 다른 노드들은 전혀 움직이지 않는 것을 관찰할 수 있어요.
- **관찰 결과:** 이것이 연결 리스트의 삽입이 O(1)인 이유예요! 배열처럼 뒤의 요소를 밀 필요가 없거든요. 포인터 몇 개만 바꾸면 끝이에요.
- **연결 질문:** 만약 각 노드가 "다음"뿐만 아니라 "이전" 노드도 기억한다면 어떤 장점이 있을까요? (힌트: 이중 연결 리스트)

## 실생활 활용

- **음악 재생목록** — 이전 곡, 다음 곡 버튼이 바로 연결 리스트의 이동이에요. 곡 사이에 새 곡을 넣기도 쉽죠!
- **브라우저 방문 기록** — 뒤로가기, 앞으로가기 버튼은 이중 연결 리스트로 구현돼요
- **다항식 표현** — 수학에서 `3x² + 2x + 1` 같은 다항식의 각 항을 노드로 저장해요
- **실행 취소(Undo) 히스토리** — 문서 편집기에서 작업 기록을 연결 리스트로 관리해요
- **이미지 뷰어** — 사진첩에서 이전/다음 사진으로 넘기는 기능이에요

## 🔗 개념 연결 고리

- **배열(Array)**: 연결 리스트와 항상 비교되는 자료구조. 접근은 배열이, 삽입/삭제는 연결 리스트가 유리해요
- **스택(Stack)**: 연결 리스트로 구현할 수 있는 대표적인 자료구조예요
- **큐(Queue)**: 연결 리스트의 양쪽 끝을 활용하면 효율적인 큐를 만들 수 있어요

## 핵심 정리

> 삽입/삭제 O(1), 접근 O(n)
