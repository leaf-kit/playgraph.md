# 동적 프로그래밍 / Dynamic Programming

큰 문제를 작은 하위 문제로 나누고, 결과를 저장하여 중복 계산을 피하는 기법입니다.

A technique that solves complex problems by breaking them into overlapping subproblems and caching results.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

동적 프로그래밍은 **메모하며 풀기**예요! 같은 수학 문제를 여러 번 풀지 않고, 한 번 풀면 노트에 적어두고 다음에 같은 문제가 나오면 노트를 보는 거예요. "3+5는 8이야"라고 적어두면, 다시 3+5가 나올 때 계산할 필요 없이 바로 8이라고 답할 수 있죠! 이렇게 하면 시간이 엄청 절약돼요.

### 📐 중학생 눈높이

계단 오르기 문제를 생각해 보세요. 한 번에 1칸 또는 2칸을 오를 수 있을 때, 10칸 계단을 오르는 방법이 몇 가지일까요? 10칸 = 9칸에서 1칸 + 8칸에서 2칸, 이렇게 작은 문제로 나눌 수 있어요. 그런데 8칸 문제는 9칸을 풀 때도, 10칸을 풀 때도 필요해요! **이미 계산한 답을 저장**해두면 같은 계산을 반복하지 않아요. 이것이 DP의 핵심이에요.

### 🎓 고등학생 눈높이

동적 프로그래밍은 **최적 부분 구조(optimal substructure)**와 **중복 부분 문제(overlapping subproblems)** 두 조건을 만족할 때 적용 가능합니다. 메모이제이션(top-down, 재귀+캐시)과 타뷸레이션(bottom-up, 반복문+테이블) 두 가지 접근이 있어요. 피보나치를 순수 재귀로 풀면 O(2^n)이지만 DP를 쓰면 O(n)! 배낭 문제, 최장 공통 부분 수열(LCS), 편집 거리(edit distance) 등 알고리즘 문제의 핵심 기법이에요.

## 🔍 어떻게 작동하는지 알아볼까요?

**피보나치 수열로 DP의 위력을 체감해 봐요!**

**순수 재귀 (중복 계산 발생!):**
- fib(5) → fib(4) + fib(3)
- fib(4) → fib(3) + fib(2) ← fib(3)이 또 나왔어요!
- fib(3)이 2번, fib(2)가 3번 계산돼요... n이 커지면 폭발적으로 증가!

**DP — 메모이제이션 (top-down):**
1. fib(5) 호출 → 메모에 없음 → fib(4) + fib(3) 계산
2. fib(4) 호출 → 메모에 없음 → fib(3) + fib(2) 계산
3. fib(3) 호출 → 메모에 없음 → fib(2) + fib(1) = 1+1 = 2 → **메모에 저장!**
4. fib(4) = fib(3)(메모에서 바로!) + fib(2) = 2+1 = 3 → 메모에 저장!
5. fib(5) = fib(4)(메모!) + fib(3)(메모!) = 3+2 = **5**

**DP — 타뷸레이션 (bottom-up):**
- 테이블: [0, 1, 1, 2, 3, 5] → 아래부터 차근차근 채우기!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 호출 트리와 테이블을 비교해 보세요. 호출 트리에서 같은 값이 여러 번 나타나는 것(중복 계산)과, 테이블에서 한 번만 계산되는 것의 차이가 확연히 보여요.
- **관찰 결과:** n=7일 때 순수 재귀는 25번 호출되지만, DP는 7번이면 끝나요! n이 커질수록 이 차이는 기하급수적으로 벌어져요. 시간 복잡도가 O(2^n)에서 O(n)으로 줄어드는 것이에요.
- **연결 질문:** DP는 "시간을 공간으로 교환"한다고 해요. 메모리를 더 써서 시간을 줄이는 건데, 메모리가 부족하면 어떻게 해야 할까요?

## 실생활 활용

- **최단 경로 알고리즘** — 다익스트라, 플로이드-워셜 알고리즘이 DP의 원리를 사용해요
- **텍스트 차이 비교 (diff)** — Git에서 파일 변경 사항을 비교할 때 LCS(최장 공통 부분 수열) 알고리즘을 써요
- **자원 배분 최적화** — 한정된 예산으로 최대 효과를 내는 조합을 찾아요 (배낭 문제)
- **음성 인식** — 말소리를 텍스트로 변환할 때 DP로 가장 유사한 단어를 찾아요
- **맞춤법 교정** — "helo"를 "hello"로 고칠 때 편집 거리(edit distance)를 DP로 계산해요

## 🔗 개념 연결 고리

- **재귀(Recursion)**: DP의 메모이제이션은 재귀에 캐싱을 추가한 것이에요
- **빅오 표기법(Big-O)**: O(2^n)이 O(n)으로 바뀌는 드라마틱한 개선을 빅오로 확인해 보세요
- **그래프 탐색**: 최단 경로 문제는 그래프 + DP의 조합이에요

## 핵심 정리

> 메모이제이션(top-down) vs 타뷸레이션(bottom-up). 시간을 공간으로 교환.
