# 재귀 / Recursion

함수가 자기 자신을 호출하여 문제를 해결하는 기법입니다.

A technique where a function calls itself to solve subproblems.

## 🌟 선생님의 다정한 설명

### 🎈 초등학생 눈높이

재귀는 **러시아 인형(마트료시카)**과 같아요! 큰 인형을 열면 안에 작은 인형이 있고, 그 인형을 열면 더 작은 인형이... 가장 작은 인형이 나올 때까지 계속 열어요. 가장 작은 인형(기저 조건)을 찾으면 다시 하나씩 닫으며 돌아와요. 자기 자신을 반복하는 것, 그것이 재귀예요!

### 📐 중학생 눈높이

거울 두 개를 마주 놓으면 거울 속에 거울이 끝없이 보이죠? 재귀도 비슷해요 — 함수가 자기 자신을 호출해요! 단, 끝없이 호출하면 안 되니까 **기저 조건(멈추는 조건)**이 꼭 필요해요. 예를 들어 5! = 5 × 4!이고, 4! = 4 × 3!이고... 1! = 1에서 멈춰요. 복잡한 문제를 작은 문제로 쪼개는 아주 강력한 기법이에요.

### 🎓 고등학생 눈높이

재귀는 문제를 동일한 구조의 더 작은 하위 문제로 분해하는 기법입니다. 기저 조건(base case)과 재귀 조건(recursive case)이 필수예요. 호출 스택에 프레임이 쌓이므로 공간 복잡도 O(n)이 기본이며, 깊은 재귀는 스택 오버플로를 유발할 수 있어요. 꼬리 재귀 최적화(TCO)는 이를 해결할 수 있지만 모든 언어가 지원하지는 않아요. 분할 정복, 백트래킹, 트리 순회 등의 기반이 되며, 동적 프로그래밍으로 확장됩니다.

## 🔍 어떻게 작동하는지 알아볼까요?

**팩토리얼 factorial(4)의 실행 과정을 따라가 봐요!**

1. **호출**: factorial(4) → 4는 1이 아니니까 → 4 × factorial(3)
2. **호출**: factorial(3) → 3 × factorial(2)
3. **호출**: factorial(2) → 2 × factorial(1)
4. **기저 조건!**: factorial(1) → 1 반환! (여기서 멈춰요!)
5. **되돌아가기**: factorial(2) = 2 × 1 = 2
6. **되돌아가기**: factorial(3) = 3 × 2 = 6
7. **되돌아가기**: factorial(4) = 4 × 6 = **24**

**호출 스택**: factorial(4) → factorial(3) → factorial(2) → factorial(1) 쌓였다가 하나씩 돌아와요!

### 🌟 선생님의 관찰 노트

- **관찰 내용:** 시각화에서 호출 스택이 쌓이는 것을 보세요. n이 커질수록 스택이 깊어지고, 기저 조건에 도달하면 하나씩 해제되는 것을 볼 수 있어요.
- **관찰 결과:** 재귀 깊이가 곧 스택 깊이예요. n=1000이면 스택 프레임이 1000개 쌓여요! 그래서 재귀가 너무 깊어지면 "스택 오버플로(Stack Overflow)"가 발생할 수 있어요.
- **연결 질문:** 피보나치 수열을 재귀로 계산하면 같은 값을 여러 번 계산하게 돼요. 이 중복 계산을 없애려면 어떻게 해야 할까요? (힌트: 동적 프로그래밍!)

## 실생활 활용

- **팩토리얼 계산** — n! = n × (n-1)!로 자기 자신을 호출하는 가장 전형적인 재귀 예시예요
- **피보나치 수열** — fib(n) = fib(n-1) + fib(n-2)로 재귀적으로 정의돼요
- **폴더 탐색** — 폴더 안에 폴더가 있을 때, 모든 파일을 찾으려면 재귀적으로 탐색해요
- **하노이의 탑** — 재귀로 풀면 아름답게 풀리는 대표적인 퍼즐 문제예요
- **프랙탈 그리기** — 나뭇가지, 눈꽃 등 자기 유사성을 가진 도형을 재귀로 그려요

## 🔗 개념 연결 고리

- **스택(Stack)**: 재귀 호출은 내부적으로 호출 스택을 사용해요. 스택을 이해하면 재귀가 보여요
- **이진 트리(Binary Tree)**: 트리 순회는 재귀의 가장 자연스러운 활용이에요
- **동적 프로그래밍(DP)**: 재귀의 중복 계산 문제를 메모이제이션으로 해결한 것이 DP예요
